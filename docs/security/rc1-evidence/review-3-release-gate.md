Things I looked for and did NOT find: `$http_host` is used only inside a map to extract the port, never forwarded; Host sent upstream is `$host$authority_port` (lower-cased, trailing dot stripped, port from config), so IPv6 literal, userinfo, trailing dot, uppercase and `host:port:port` tricks cannot change what the backend sees (userinfo/IPv6 Hosts do not match server_name and land in the 404 default server; nginx rejects duplicate Host headers with 400). `if` use is limited to `return`/`set` (the safe subset) in server and location context; `set $origin_seen` precedes its `if`s; `$authz_reason` is unset when the rewrite-phase `return 403` fires, so it correctly yields 403 not 429; error_page 403 does not intercept upstream 403s (proxy_intercept_errors off). X-Authz-* headers are overwritten by proxy_set_header on the subrequest, and the 8081 server listens on 127.0.0.1 inside the gateway container only. `limit_except GET POST` plus `X-Authz-Method` = `$request_method` (main request method) means HEAD/other verbs are never charged and PUT/DELETE get 403. Regex locations: `$` in PCRE matches before a trailing newline (`/api/launch%0A` matches the attack location), but that only routes to the stricter location; the reverse (an attack route reached through the learner/404 locations) is not possible because Flask has no route for the odd path. Backends never read X-Auth-Role/X-Remote-User (grep: no use). No secret reaches logs, errors or status payloads (audit is hash-only; status shows stage states only; REST URL never echoed).
