# Independent security review 2: de75241..HEAD (feature/v1.3.0-unified-gateway)
Method: read-only (git diff, Read, Grep). Tests not trusted. No runtime access, so nginx/Splunk behaviour is marked where it matters.

## Findings

F1 MEDIUM (regression) - Online password guessing is now unthrottled. gateway/attack-enabled.conf (removed `limit_req zone=attack`), gateway.conf.template:11-12.
 Before: `limit_req` (per $binary_remote_addr, 6r/m, burst 5) ran in the preaccess phase of the attack locations, i.e. BEFORE auth_basic, so guessing the `operator` password against /api/launch... was throttled per IP.
 Now: the only limiter lives in the 8081 subrequest, reached only after auth_basic succeeds and keyed on the authenticated user. Nothing limits failed Basic attempts on any route. docs/gateway_config now warns "no per-account lockout", but the earlier partial mitigation is gone.
 Exploit: unlimited `curl -u operator:guess https://host/api/launch` at network speed; the only defence is password entropy. Confidence: confirmed-by-reading.
 Fix: add a second per-IP `limit_req_zone $binary_remote_addr` (generous, e.g. 30r/s... or 10r/m on 401 path) at server level, or `limit_req` before auth_basic.

F2 LOW-MEDIUM - Cross-site POST can burn the operator quota (CSRF-DoS). gateway.conf.template:11-12 vs request_guard.py.
 The quota is charged in the auth subrequest (nginx), the cross-origin check happens later in Flask. A page on another origin can make an operator's browser POST to /api/launch (Basic credentials attach on top-level form navigation). nginx authenticates, sees operator+POST, charges the single shared bucket "operator" (6/min, burst 5); Flask then returns 403 cross_origin_rejected. Six such POSTs lock the real operator out with 429 for ~10 s each cycle; repeated, indefinitely.
 Also: every POST that the backend later rejects (415/400/413) charges quota; the bucket is shared by all sessions of the operator account.
 Confidence: plausible (needs a browser that sends cached Basic creds cross-site; Chrome partitions auth cache for subresources but not for top-level form POST). Fix: in the 8081/main location reject `$http_sec_fetch_site` in {cross-site,same-site} and non-matching Origin before auth_request.

F3 LOW - Port normalisation gaps (fail-closed lockout, not a bypass). gateway_config.py:76-77, template:20-23.
 `port.isdigit()` accepts "0443", "00443", and non-ASCII Unicode digits; nginx `map` matches only literal 443. PUBLIC_PORT=0443 passes validation, authority_port=":0443", but browsers send Host without port => `421` on every request. Reverse: client Host `host:123456` (6 digits) does not match `{1,5}` regex, so client_port="" and on a 443 deployment passes (harmless: upstream Host is rebuilt from $host$authority_port, never the client port). Fix: validate `^[1-9][0-9]{0,4}$` ASCII.

F4 LOW (latent) - SPL policy does not cover shell metacharacters on the reconcile docker-exec path. loan_desk/reconcile.py:45 with spl_policy.check.
 `json.dumps(spl)` embedded inside bash double quotes (`bash -lc`): `$(...)`, `${SPLUNK_PASSWORD}`, `$VAR` are expanded by bash in the Splunk container. spl_policy blocks backtick but accepts `$`, `(`, `)`, `\`. Any attacker-influenced SPL on this path = command execution as `splunk` and disclosure of the admin password via results. Today the inputs are a fixed template plus a UUID-validated run id (not exploitable). The module docstring/commit message present the policy as the control for the admin-credential path; it is not for this one. search.py's env-var path (`-e AGENTSEC_SPL=...`, `"$AGENTSEC_SPL"`, exec) is correct and not affected. Fix: use the env-var mechanism in reconcile.py, or reject `$` and `\`. Confidence: confirmed-by-reading.

F5 LOW - ssl/headers: named locations @attack_denied and @quota use add_header, which drops the http-level HSTS / nosniff / X-Frame-Options / Referrer-Policy on 403/429 responses from attack routes (nginx add_header inheritance). Low impact (JSON/empty bodies). Confirmed-by-reading.

F6 LOW - Status probe resource use. academy_web.py probe_splunk_rest: cache has no lock and is bypassed for concurrent callers once stale, so N polling learners can each run `diagnose()` (server/info + a search job on the Splunk token) simultaneously; unreachable endpoint holds Flask worker threads for the REST timeout. Learner-authenticated only. Fix: lock or single-flight refresh.

F7 INFO - Probe URLs: AGENTSEC_SPLUNK_INTERNAL_URL / AGENTSEC_SPLUNK_WEB_URL are env only; no learner input reaches them (SSRF not reachable by a learner). They are not scheme-checked: urllib would also open file:// or follow redirects if an operator misconfigures. Response carries only state/detail, never the URL or body. Status detail does disclose stage names, mode, and error code (`REST_URL_INVALID` etc.) to any authenticated learner.

F8 INFO - request_guard (non-gateway paths): Origin == Host comparison trusts the Host header, so DNS rebinding to a direct-published port (5001) still passes (Host and Origin both attacker.com:5001). Gateway mode is not affected: Host is rebuilt from config. Origin scheme is not compared to the real scheme (http://host vs https://host with default port compare equal); modern browsers add Sec-Fetch-Site=same-site which is rejected, so only legacy browsers. Requests with neither header pass by design.

F9 INFO - Policy messages: SplunkError(str(exc)) / the "command 'X' is not allowed" message echo the command token (charset [A-Za-z0-9_]) taken from the SPL, though the docstring says the text is never echoed. Audit hash is sha256[:16] of low-entropy SPL (run id inside): not a secret. Policy also does not bound makeresults count / mvrange / sort size (resource exhaustion), and any `index=` is accepted in the base stage (scoping relies on the token). Internal SPL only.

F10 INFO - 421 is evaluated at server rewrite phase, before auth_basic: an unauthenticated client learns only "wrong port" (no data). Not a bypass: `return` ends the request with no upstream. An anonymous DELETE/PUT gets 403 (limit_except deny precedes auth) instead of 401: still denied.

## Checked and found sound (by reading)
- Auth bypass: auth_basic is at server level, inherited by every location including the learner regex location, the attack regex location, `location /` and @attack_denied (internal redirect re-runs access phase with same credentials). `if ($client_port_norm != $authority_port) return 421` only ever denies. error_page 403 = @attack_denied only rewrites 403 -> 403/429 (proxy_intercept_errors is off so backend 403s are not remapped). `auth_request_set $authz_reason` is set only from the loopback subrequest response; the client cannot set it.
- Role: $remote_user comes from htpasswd; 8081 server is bound to 127.0.0.1 inside the gateway container (not on the mesh); X-Authz-User and X-Authz-Method are overwritten by proxy_set_header (client copies are dropped; underscore variants ignored by default). A client-supplied `X-Authz-Method: GET` cannot suppress the charge. Role check is an `if`/return in the rewrite phase, so learners and anonymous never reach limit_req. Quota key is empty (uncounted) unless user==operator and method==POST, so unauthorized users can neither spend nor exhaust it. An operator cannot dodge it with another mutating method: limit_except GET POST; lowercase/unknown methods are denied. Only GET/HEAD escape the quota; I found no GET route with side effects in the routed paths.
- Path confusion: attack and learner regexes are disjoint; PCRE `$` before a trailing newline only widens the attack match (stricter). Learner locations are GET-only. Upstream receives the raw URI, but normalized and raw forms route to the same Flask route; no learner-regex prefix (learn/, static/) maps to an attack route in Flask.
- Host/CSRF: upstream Host = `$host` + configured authority (never X-Forwarded-*, never client port); duplicate Host headers are rejected by nginx; $host is lowercased and the guard lowercases both sides. X-Forwarded-For/Proto are overwritten, backends have no ProxyFix and don't trust them (only request.host). Learn config returns null Splunk/AcmeBank URLs in gateway mode, removing the Host reflection into JSON there.
- SPL policy: policy checks the SAME normalised text that is sent (REST export_csv and both docker paths use the returned value). Every `|` is a stage boundary regardless of quotes; backtick, `[`, `]`, non-ASCII, control chars rejected after normalisation (Unicode whitespace is folded to spaces before the ASCII test); allowed stage commands (eval, fillnull, head, rename, sort, stats, table, where) have no write/exec side effects, no subsearch syntax without brackets, no macro syntax without backticks; `| |` and `||` produce empty stage names and are rejected; first stage cannot become a command without a pipe. `index=` outside the base stage is rejected. Learners cannot supply any SPL (templates use enums/bounded ints, UUID run ids). REST path prepends `search` only when needed.
- docker-exec in loan_desk/search.py: argv list (no host shell), SPL in an env var and `exec ... "$AGENTSEC_SPL"`; container name regex-validated.
- gateway.sh: CA key removed on every exit path via trap; name constraints present; ext.cnf written via printf %s; HOST/PORT only from operator env. Residual: a failed init leaves a partial directory (script then refuses to rerun) and HOST is interpolated into `-addext` (operator-controlled, validated by HOST_RE in `validate`, not in `init`).
- Compose hardening: no docker.sock, privileged, or cap_add anywhere in base or overlay; attack_service/acmebank Dockerfiles use `USER appuser` with no gosu/su-exec, so `cap_drop: [ALL]` is safe; gateway keeps CHOWN/DAC_OVERRIDE/FOWNER/KILL/SETGID/SETUID which the nginx root master needs; NET_BIND_SERVICE drop is fine (8443). no-new-privileges does not block nginx's setuid() to the worker user. Splunk Web/HEC rebound to loopback only. `pids_limit: 128`/`mem_limit: 128m` on a many-core host with `worker_processes auto` could in theory hit the pid cap (needs runtime confirmation).

## Needs runtime confirmation

- Default (non-SNI-matching) server answers 404 with no body leakage when Host does not match server_name.
