# Security tools in AgentSecLab

What each tool is, what the lab does with it, and what it does not do. Versions come from the repository's pin files (`tools/*/pin.json`), the compose files and the dependency manifests. Licences were read from each project's upstream `LICENSE` file on GitHub on 2026-10-29 (garak Apache-2.0, Ollama MIT, nginx BSD-2-Clause, OpenTelemetry Collector contrib Apache-2.0, Cisco MCP Scanner Apache-2.0); the Llama and Splunk terms are not open-source licences, so read them yourself.

| Tool | Version | Licence | Install method | Use in the lab | Status | Limits |
|---|---|---|---|---|---|---|
| **Cisco MCP Scanner** (`cisco-ai-mcp-scanner`) | 4.8.4 (pinned wheel, SHA-256 recorded) | Apache-2.0 | Isolated Python environment created by the installer from the pinned wheel | Static, YARA-only scan of a tool-catalog artifact; results are normalized and ingested to Splunk by a script | **Operational**, optional to run | No API key and no language model are used. The dashboards show committed scanner packs unless you run the scanner. A scan of one artifact is not an assessment of a real MCP server |
| **garak** (NVIDIA) | 0.17.0 | Apache-2.0 (upstream `LICENSE` checked 2026-10-29) | Not installed by the lab | Reads a **recorded** garak result (`dan.Dan_11_0` against `llama3.2:1b`) from a committed pack, ingested by a script | **Recorded evidence only** | One run, not a rate. Not a measurement of any model or product. The lab does not run garak |
| **Ollama** | image `ollama/ollama` (`latest` in the compose file, not digest-pinned) | MIT | Docker image started by Compose | Serves the two local models | **Operational** | CPU only; results vary with the model, Ollama version and sampling |
| **Llama 3.2** models (`llama3.2:1b`, `llama3.2:latest`) | as pulled by Ollama | Llama 3.2 Community License (not an open-source licence; read its terms) | Pulled by Ollama on first install | The language model behind live labs and the Loan Desk | **Operational** | Small models; no claim about their security |
| **Splunk Enterprise** | 10.2 image; 10.2.7 in the acceptance run | Splunk's own terms (proprietary); the lab does not redistribute it | `splunk/splunk` image pulled by Compose | Index `agentsec_telemetry`, HEC ingestion, investigation searches, assurance dashboards | **Operational** | Needs a Linux kernel older than 6.19 for its database. Splunk Web has its own login and is outside the gateway |
| **OpenTelemetry Collector (contrib)** | 0.96.0 | Apache-2.0 | Docker image | Receives agent events and sends them to Splunk HEC over TLS | **Operational** | Loopback ports only |
| **nginx** | 1.27-alpine | BSD-2-Clause | Docker image | The HTTPS gateway | **Operational** | Basic authentication with two roles; for one local participant |
| **CSA MAESTRO** | v1 framework | CSA publication (not software) | Implemented as a browser workbench | Seven-layer threat modeling | **Operational** (browser only) | Does not run CSA's MAESTRO Threat Analyzer; does not implement v2 |

Anything not in this table is not integrated. Nemotron has not been evaluated; the dashboard panel says "Not tested". Where this page says "recorded", the evidence was captured earlier and committed; where it says "operational", it ran in the acceptance runs described in the [installation guide](INSTALLATION_AND_DEPLOYMENT.md). Other docs: [Cisco MCP Scanner integration](CISCO_MCP_SCANNER_INTEGRATION.md), [garak evaluation](GARAK_EXTERNAL_EVALUATION.md), [attributions](EXTERNAL_TOOL_ATTRIBUTIONS.md).
