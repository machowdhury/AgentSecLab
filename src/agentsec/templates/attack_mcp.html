Can an AI agent use a tool it was never granted?

You will test one request against AcmeBank's loan assistant. You predict first, then work out what happened from evidence.

The story

To answer lending questions, the assistant may use one tool, {{ mcp_policy.allowed_tools }}. A second tool, {{ mcp_request.tool }}, exists in the system. This agent was never granted it.

The question

If the assistant asks for a tool it was not granted, does the control stop the request? And does the tool still run? Those are two different facts.

Your route

Understand normal behavior, make a prediction, run the attack, investigate the evidence, test a defense, compare, then explain what you can safely claim.

STEP 5 OF 8 · IMPROVE · DEFEND · after you have investigated ATTACK · an explanation, not a control

Understand the defense

Next you repeat the same request against a defended configuration. Here is what changes, and what does not.

Same

The request

The same agent asks for {{ mcp_request.tool }} with the same scope and arguments. Nothing about the request changes.

Different

The server's configuration

The defended profile is configured to enforce the agent's grant list: a tool the agent was not granted should not proceed. The server chooses the profile; the browser cannot.

Whether it actually does is what RETEST measures. A configuration is a claim; the evidence is the proof. RETEST shows how this one request behaved under this profile. It does not show the system is secure.

There is no “apply defense” button on purpose: the security profile is chosen by the server, not by a browser.
